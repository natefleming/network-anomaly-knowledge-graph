The problem

Network anomalies hide between the rows

Traditional SIEM and SQL alerts treat each event in isolation. The signal that matters lives in the relationships:

  • A port-scanner is only obvious when you see all its destinations together
  • Lateral movement is a chain, not a row
  • Exfiltration is a ratio across many flows
  • A rogue device is defined by what it doesn't talk to

Row-by-row alerting

Misses anything that requires multi-hop reasoning across hosts, ports, and time windows.

Static rules

Break the moment attacker behavior shifts. Maintaining hundreds of brittle SQL alerts is its own job.

Graph thinking

Entities are nodes, traffic and resolutions are edges. Anomalies become patterns the graph naturally surfaces.

Hosts, services, subnets, and external IPs are first-class entities — not rows in a denormalized log.

2

Relationship-first

Edges carry weight, direction, timestamps, and rich attributes. Who talks to whom, how much, when, why.

3

Multi-hop reasoning

"Did this rogue device's neighbor's neighbor ever ping our payments DB?" is a single graph query.

4

Schema-flexible

Each entity type carries its own attribute payload via VARIANT — no painful star-schema gymnastics.

5

Explainable

Every flagged anomaly comes with the subgraph of evidence — you can show the analyst why.

6

Composable

The same nodes/edges power dashboards, notebook analytics, the app, and downstream ML.

Databricks ·05
The graph in two tables

Nodes and edges, both with VARIANT attrs

Every entity in the network — hosts, subnets, services, external IPs — is a row in gold_graph_nodes. Every relationship — flows, DNS resolutions, service-runs-on, host-in-subnet — is a row in gold_graph_edges. The attrs column on each is a Databricks VARIANT, carrying a different shape per node/edge type. Bronze events conform to the OCSF standard (Network Activity class_uid=4001, DNS Activity 4003).

gold_graph_nodes — 5,397 rows

CREATE OR REFRESH MATERIALIZED VIEW gold_graph_nodes
CLUSTER BY (node_id, node_type) AS
  node_id        STRING        -- 'host:H-0207'
  node_type      STRING        -- host|subnet|service|external_ip
  label          STRING        -- hostname / cidr / service_name
  attrs          VARIANT       -- per-type JSON payload
  criticality    INT           -- 1..5, host nodes only
  subnet_id      STRING
  is_external    BOOLEAN
  host_type      STRING
  anomaly_score  DOUBLE        -- max across detectors
  anomaly_labels ARRAY<STRING> -- ['port_scan','rogue_device',…]
VARIANT attrs payload per node_type:
host · ip, host_type, os, owner, criticality, zone, cidr, last_active_ts, flow_total
subnet · cidr, zone, description
service · host_id, port, protocol, service_name
external_ip · ip, total_bytes, flow_count, distinct_internal_callers, last_seen_ts

gold_graph_edges — 32,734 rows

CREATE OR REFRESH MATERIALIZED VIEW gold_graph_edges
CLUSTER BY (src_id, dst_id, edge_type) AS
  src_id         STRING
  dst_id         STRING
  edge_type      STRING        -- flow|resolves|hosts|in_subnet
  packet_count   BIGINT
  byte_count     BIGINT
  flow_count     BIGINT
  is_cross_zone  BOOLEAN
  is_anomalous   BOOLEAN
  anomaly_label  STRING
  anomaly_score  DOUBLE
  last_seen_ts   TIMESTAMP
  attrs          VARIANT       -- edge-type-specific
VARIANT attrs payload per edge_type:
flow · src_zone, dst_zone, is_cross_zone, distinct_dst_ports[], distinct_protocols[], byte_count, flow_count, avg_duration_ms
resolves · query_count, sample_queries[], query_types[], is_suspicious_tld
hosts · port, protocol, service_name
in_subnet · zone, cidr

Databricks ·07
What the graph surfaces

Five anomaly patterns, all from the same nodes + edges

Port scan · gold_anomaly_scan

Rule: ≥30 distinct dst hosts AND ≥30 distinct dst ports in a 10-min window.

Visual: starburst from one red node. Seeded: H-1027 → 60 hosts × 6 ports.

Lateral movement · gold_anomaly_lateral

Rule: 3-hop chain via self-joins (a→b→c→d) where each hop's dst is next's src, crossing ≥3 zones in 15 min.

Visual: snake across subnets. Seeded: 3 chains.

Data exfiltration · gold_anomaly_exfil

Rule: >5 MB outbound to a single external IP in a 5-min window, per (src, dst_ip).

Visual: thick red edge leaving the cluster. Seeded: H-1793 → 185.220.101.42, ~25 MB.

Rogue device · gold_anomaly_rogue

Rule: internal host with flow_count = 0 AND ≥1 DNS query to a flagged TLD (.xyz/.top/.tk/.click/.ru/.pw/.cc/.bid).

Visual: purple isolate at periphery. Seeded: 5 rogues.

DDoS target · gold_anomaly_ddos

Rule: ≥50 distinct sources hitting one dst in a 5-min window.

Visual: fan-in. Seeded: H-1447 from 150 sources (tops the GraphFrames degree-centrality ranking at 195).

Each detector is a single materialized view in pipelines/gold/ — <40 lines of SQL each. Scores between 0 and 1; multiple flags merge into anomaly_labels on the node.

In the app

Anomalies have shapes — and the app draws them

Blue · normal host

Workstation with expected peer connections. Clusters tightly near its gateway.

Green · server / gateway

High legitimate fan-in. Sits at the center of normal subnet clusters.

Yellow · elevated (pulsing)

anomaly_score > 0.5. Pulses to draw attention without alarm.

Red · confirmed (glowing)

anomaly_score > 0.85. Radial glow, animated red particles on its edges.

Purple · rogue

Floats at the periphery with no flow edges — only DNS resolves.

Edge particles

Anomalous edges get 6 particles at 4× normal speed. Normal flow = 1 slow particle.

Databricks ·09
Querying the graph

Same SQL, schema-less attributes

Every node and edge carries a VARIANT column. Query attributes with the attrs:field::type operator — no joins back to bronze. 

-- "Where is cross-zone traffic flowing — and how much?"
SELECT
  attrs:src_zone::string AS src_zone,
  attrs:dst_zone::string AS dst_zone,
  SUM(CAST(attrs:byte_count   AS BIGINT)) AS total_bytes,
  SUM(CAST(attrs:flow_count   AS BIGINT)) AS total_flows
FROM gold_graph_edges
WHERE edge_type = 'flow'
  AND attrs:is_cross_zone::boolean = TRUE
GROUP BY ALL
ORDER BY total_bytes DESC;

Notebook 03_anomaly_queries ships nine more — port-scan via attrs, rogue-device join across nodes + edges, top external destinations by byte_count, service-targeted-port roll-ups, and more.

Databricks ·10
When SQL isn't enough

GraphFrames for graph-shaped questions

GraphFrames is the current state of the art for distributed graph processing on Spark — GraphX was deprecated in Spark 4.0.

Algorithms in 02_graph_analytics

  • Degree centrality — surfaces gateways AND port-scanners simultaneously
  • Connected components — isolates the rogue-device subgraph
  • Motif finding — declarative path patterns: (a)-[]->(b); (b)-[]->(c); (c)-[]->(d)
  • BFS / reach analysis — what could a rogue touch if it pivoted?
# Build the graph from the gold tables
from graphframes import GraphFrame

vertices = spark.table("gold_graph_nodes") \
  .withColumnRenamed("node_id", "id")
edges    = spark.table("gold_graph_edges") \
  .withColumnRenamed("src_id", "src") \
  .withColumnRenamed("dst_id", "dst")

g = GraphFrame(vertices, edges)
chains = g.find("(a)-[e1]->(b); (b)-[e2]->(c); (c)-[e3]->(d)")

The Databricks SIEM

Introducing Databricks Lakewatch

Announced March 2026. Lakewatch is Databricks' new open, agentic SIEM — it brings security information and event management directly into the lakehouse, normalizes telemetry on OCSF, and pairs detection-as-code with Mosaic AI agents that triage and investigate. Currently in Private Preview.

① Ingest

Managed connectors for CrowdStrike, Okta, AWS CloudTrail, and more — plus cloud storage or existing workspace tables.

② Normalize on OCSF

Open Cybersecurity Schema Framework brings every source into a consistent shape (class_uid, activity_id, src/dst_endpoint, traffic, …).

③ Detect threats

SQL-based detection rules on schedules with prebuilt templates. Versioned. Tested. Deployed as code.

④ Investigate cases

Security cases auto-correlate related alerts and track entity risk scores across the graph of activity.

⑤ Ad-hoc SQL

Time-range filtering, row-level inspection — analyst-grade SQL in the Lakewatch UI directly over OCSF gold.

⑥ Investigate with AI

Genie + Agent Bricks plan multi-step investigations, parse hundreds of telemetry formats, and surface the why.

Architecture: bronze (raw) → silver (cleaned / presets) → gold (OCSF-normalized) → detection rules · security cases · observables · ad-hoc · AI investigation.

The migration story

What we built ≈ Lakewatch, hand-rolled

The pieces of this demo map 1:1 onto Lakewatch primitives, so when Lakewatch GAs the migration is mostly re-pointing detection rules at the same OCSF-aligned (Open Cybersecurity Schema Framework) gold tables.

Bronze · raw events

Lakewatch: managed connectors land raw security data.
This demo: bronze_network_flows, bronze_dns_queries, bronze_hosts, bronze_subnets, bronze_services.

Silver · presets / enrich

Lakewatch: built-in presets normalize per source.
This demo: silver_flows (cross-zone flag), silver_dns (suspicious-TLD flag), silver_hosts, silver_services.

Gold · OCSF-normalized

Lakewatch: OCSF gold drives every consumer.
This demo: bronze + silver carry OCSF class_uid (4001 / 4003), src_endpoint.*, traffic.*, query.* on every event row — same standard.

Detection rules · SQL · as-code

Lakewatch: scheduled SQL detections with prebuilt templates.
This demo: the five gold_anomaly_* MVs — each <40 lines of SQL, version-controlled in the bundle.

Observables · entity risk

Lakewatch: extracted entities with risk scoring.
This demo: gold_graph_nodes with anomaly_score + anomaly_labels rolled up across detectors.

Security cases · correlation

Lakewatch: auto-correlates related alerts into cases.
This demo: the next step — a gold_security_cases MV that joins gold_anomaly_* by overlapping node_id or time window.

AI investigation · Genie

Lakewatch: Genie + Agent Bricks for NL investigation.
This demo: point Genie at gold_graph_nodes + gold_graph_edges — VARIANT attrs and column COMMENTs already give it the semantics it needs.

Analyst UI · query + drill

Lakewatch: built-in UI with time-range + row-level inspection.
This demo: the React + force-graph app — anomaly tiles, search/highlight, node + edge detail drawer.
